# Зона симуляции — Blender 2.12.2 / пакет v06

Сцена: outputs/City_Web_Contract/simulation_zone_v01/Editable_Simulation_Zone.blend.
Объект: **SIM • Район проектов — граница симуляции**.
ID: `simulation.portfolio`. Прямоугольник согласован пользователем.

Граница в Blender: X от −70 до 65 м, Y от −105 до 115 м, высоты Z от −2 до 150 м.
Размер 135 × 220 м: все восемь точек проектов, парковка, часть обоих мостов,
улица за стартом до первой линии высоток. Это граница работы актёров, а не
обрезка видимого города: здания и дальние улицы продолжают отображаться.

Результат: 83 пути имеют участки внутри, 6 въездов и 6 выездов. Пешеходные
пути тоже проверяются; в текущей зоне они целиком внутри, поэтому на границе
получились только автомобильные порталы. Два существующих конца задней
поперечной улицы находятся внутри зоны: они перечислены в internalTerminalNodeIds.

## Как поменять и запечь самостоятельно

1. После установки 2.12.2 полностью перезапустить Blender: открытое окно не
   перезагружается автоматически. Открыть указанную новую сцену.
2. N → **Разметка сайта → Граница симуляции → Выбрать: SIM…**.
3. G — переместить, S/X/Y — изменить размер, Tab — править вершины одной грани.
   Контур должен остаться горизонтальным и без самопересечений. Не экструдировать
   его в коробку. Форма может быть вогнутой; отверстия/несколько граней пока не поддержаны.
4. В этой же панели отдельно меняются нижняя/верхняя мировые высоты. Высота
   нарисованной плоской грани — только положение вспомогательного контура.
5. **Запечь входы и выходы зоны…** → выбрать `road-network.json` нужного пакета.
   Сейчас это outputs/City_Web_Export/actors-runtime-candidate-v06/road-network.json.
6. Новый результат и точная копия выбранной сети появятся в
   `Simulation_Bakes/<UTC-время>/` рядом с .blend. Путь виден в поле «Последний JSON».
   Старый пакет не перезаписывается. Если выделена зона — запекается она;
   иначе запекаются все размеченные зоны сцены. Сохранить .blend, чтобы сохранить правки.

Новую область можно создать кнопкой «Создать зону симуляции» у 3D-курсора или
пометить свою отдельную горизонтальную грань кнопкой «Выбранная грань → зона».
ID присваивается при создании и сохраняется при движении. У копии нужно задать
другой ID; повторы отклоняются. Модификаторы/shape keys нужно применить явно.

Выбранный JSON должен соответствовать дорогам в этой сцене. Проверяются ID,
связи, ширина, режим и геометрия: принимаются исходные точки или их стандартное
сокращение с допуском 2 см. Старая/другая сеть отклоняется вместо тихого запекания
по неверным координатам. Изменение только контура не требует повторного экспорта GLB.
После изменения самих дорог/сигналов нужен новый городской пакет и новое запекание.

## Передача сайту

Пакет: `actors-runtime-candidate-v06`. Добавлен `simulation-zones.json` в
candidate-manifest.json → assets. Три GLB побайтово взяты из v05; остальная сеть
не менялась, кроме exportId пакета. Хэш GLB и хэш дорожного JSON связывают данные.
Внутренний glTF asset.extras сохраняет исходный export ID геометрии; идентичность
пакета определяется manifest/exportId и SHA, а не переписыванием бинарных ресурсов.

Верхний объект:

| Поле | Смысл |
|---|---|
| schemaVersion / kind | `1` / `city-simulation-zones` |
| exportId | Версия того же пакета и дорожной сети |
| citySha256 | SHA256 используемого city.glb |
| roadNetwork.url / sha256 | Точный JSON сети; SHA от его байтов, не от JSON.stringify |
| coordinates | Метры, Y вверх, перед −Z, world |
| zones | Независимые размеченные области |

Для зоны:

| Поле | Смысл |
|---|---|
| id / name | Постоянный ID и отображаемое имя |
| boundaryXZ | Контур в горизонтальных XZ сайта; Blender `(x,y,z)` → `(x,z,-y)` |
| minHeightMetres / maxHeightMetres | Нижняя/верхняя координата Y на сайте |
| boundaryPolicy | `included`: движение вдоль самой границы считается внутри |
| activationRule | `actor-origin-in-prism`: решение по origin актёра, не по всему кузову |
| edgeIntervals | `edgeId`, `mode`, массив участков `[startDistanceMetres, endDistanceMetres]` |
| portals | Точные направленные пересечения: entry / exit |
| activeJunctionIds / activeSignalGroupIds | Связанные с активными путями перекрёстки/группы |
| internalTerminalNodeIds | Обычные концы дорог, которые оказались внутри |

Портал содержит `id`, `zoneId`, `edgeId`, `mode`, `direction`,
`distanceAlongMetres`, `position`, единичный направленный `tangent` и `intervalIndex`.
В соответствующем interval лежат entryPortalId/exitPortalId, если есть пересечение.
Все расстояния — **от начала исходного полного направленного ребра**, в метрах
по его 3D-ломаной, включая подъём моста. Это не проценты и не расстояния от границы.

Пример использования: машина появляется на въезде не на points[0], а на
`portal.distanceAlongMetres` своего edgeId. Во время движения нужно соблюдать
конец активного interval, даже если он находится в середине ребра. Просто взять
список active edgeId и ездить по каждому целиком недостаточно — это выпустит
машину за зону. Сайт сам выбирает количество/маршруты/свободное место/зазор;
automaticSpawnAllowed=false означает, что сам JSON не является командой спавна.

Порталы обычно находятся посреди ребра и не являются новыми узлами from/to:
полный граф специально не разрезан. При точном совпадении границы с узлом
добавляются graphNodeId и outsideAdjacentEdgeIds. Выезд в этом случае применяется
при выборе внешнего соседнего пути; переход на соседний внутренний путь не
обязан уничтожать актёра. Чистое касание угла без ненулевого внутреннего участка
не создаёт портал. Длинный путь outside → inside → outside и вогнутые контуры
с несколькими заходами учитываются полностью. ID порталов детерминированы по
зоне/ребру/номеру внутреннего участка/направлению; изменение топологии пересечений
требует обновить запекание и не переносить старое состояние актёров вслепую.

Эта зона не заменяет пешеходную поверхность: свободным пешеходам нужны допустимые
поверхности и их пересечение с объёмом симуляции. Сеть/порталы не управляют фазами,
приоритетом, разводкой мостов или столкновениями. Статус — baked geometry,
не новая runtime-приёмка. Веб-код и активный URL пакета автоматически не менялись.

## Код и повторение

- `site/authoring/simulation_zones.py`: Blender Mesh/ID/мировые координаты и отдельное запекание.
- `site/exporting/simulation_zones.py`: чистая геометрия, интервалы и порталы, без bpy.
- `site_authoring_ui.py`: три команды и поля панели; вычислений геометрии в UI нет.
- Штатный native export добавляет optional simulationZones в manifest и исключает
  вспомогательную грань из GLB/проверки статических препятствий даже при hide_render=False.
- CLI экспорта библиотек тоже пишет sidecar; сокращение путей пересчитывает его
  заново после изменения геометрии/длин и связывает с новым хэшем сети.
- `work/simulation_zone/`: сборка сцены, CLI запекания, пакет и изображения.

Запекание сохранённой сцены одной командой:

```powershell
& 'C:\Program Files (x86)\Steam\steamapps\common\Blender\blender.exe' --background --factory-startup --python work/simulation_zone/bake.py -- 'сцена.blend' 'road-network.json'
```

Тесты: 10 геометрических регрессий, независимый slab-algorithm для всех 137 рёбер,
настоящие Blender-операторы/повторное открытие/отказ stale JSON/зеркальный scale,
реальный native export с зоной и цепочка actor export → сокращение → повторное
запекание. Изображения осмотрены. Интерактивный UI и браузерная симуляция не
объявляются проверенными одним лишь background-тестом.
